## Live (ByteStash, `http://192.168.2.10:5000/mcp`)

**Surface.** `GET /core/mcp/servers` reports the generated toolset:

```
{ name: bytestash, transport: http, state: connected, toolCount: 6,
  toolset: "mcp-bytestash" }
```

**Selection — bare server alias.** `TOOLS_ENABLED_TOOLSETS=bytestash`
(opt-in, so *only* aliased tools are offered):

```
model called mcp_bytestash_list_snippets {} → approved → returned 23 snippets
```

Without the alias, opt-in to the literal `bytestash` would offer zero tools, so
the call proves the bare-name alias selects `mcp-bytestash`.

**Composition — shared name with a built-in toolset.** Registered a second
server named `browser` (same endpoint) and set
`TOOLS_ENABLED_TOOLSETS=browser`:

```
mcp_browser_list_snippets {}  → approved → returned 23 snippets   (MCP, via alias)
browser {action:"navigate", url:"https://www.iana.org"}
                              → page title "Internet Assigned Numbers Authority"  (built-in)
```

Both the built-in `browser` toolset and `mcp-browser` were offered and worked —
composition, not shadowing.

**Aggregate alias** (`mcp` → every generated toolset) is covered by the unit
matrix; the live run used the bare-name and shared-name paths.
