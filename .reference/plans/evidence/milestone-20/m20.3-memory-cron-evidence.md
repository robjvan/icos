# M20.3 — Memory ledger & Cron surfaces: evidence

> Status: **verified** (2026-10-10). Slices **M20g** (ledger ranking) and
> **M20h** (cron surface). Per-slice evidence; M20 is in progress.

## M20g — Memory ledger ranking

- **Backend:** `listCandidates` accepts a `sort` — `recent` (default,
  insertion order), `confidence`, `importance`, `stability`. The SQLite
  repository maps the key through a **fixed ORDER BY allowlist** (never
  interpolated from input); the DTO validates it (`@IsIn`); the controller
  passes it through.
- **Client:** the Memory tab's ledger gains a **rank selector**; the stale
  "ranking unimplemented (M10–M12)" badge is replaced with
  "evidence ledger · rankable".

## M20h — Cron surface

- **Backend:** a `CronController` (`GET/POST /core/cron`,
  `POST /core/cron/:id/{pause,resume,run}`, `DELETE /core/cron/:id`) mirroring
  the `cronjob_manage` tool. Mutations are admin-only; reads are open.
- **Client:** the Cron tab is real — list jobs, create (name + 5-field cron +
  prompt), pause/resume, run-now (shows the run result), and delete with an
  inline confirm.
