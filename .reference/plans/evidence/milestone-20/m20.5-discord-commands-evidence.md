## What was built

- **Single source of truth.** `CommandRegistry.descriptors()` /
  `CommandDispatcher.commandDescriptors` expose the internal catalog; the
  adapter registers it as Discord **application commands** on ready, so Discord
  is never a second definition. `commands.set(...)` **overwrites** the app's
  command set — the stale "Hermes commands" are cleared by the same call.
- **CHAT_INPUT routing.** `DiscordAdapter` routes `isChatInputCommand`
  interactions to a new `onCommand` handler; `DiscordIngressService` builds
  `/<name> <text>`, dispatches via `CommandDispatcher` in the conversation's
  session, replies (deferred → `editReply`), and rebinds the conversation when a
  command switches session (`/new`, `/fork`).
- **Args:** one generic optional `text` STRING option (the raw args), kept
  scoped — no per-command option modelling (per the note's "don't turn this into
  a second Discord project").
- `CommandDispatcher` is exported from `ConversationModule` so `ChannelsModule`
  can inject it.
