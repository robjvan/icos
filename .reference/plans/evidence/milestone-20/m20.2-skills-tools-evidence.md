# M20.2 — Skills & Tools surfaces: evidence

> Status: **verified** (2026-10-09). Slices **M20e** (skills view/edit/delete)
> and **M20f** (tool inventory + auto-approve). Per-slice evidence; M20 is in
> progress.

## M20e — Skills view/edit/delete

- **Backend:** `PUT /core/skills/:name` updates description + body while
  **preserving the rest of the frontmatter** (version/author/license/metadata),
  so editing a shipped skill no longer strips its metadata. Service spec added.
- **Client:** the Skills tab gained a modal with inline **view/edit/delete**,
  **hover row actions** (the edit icon opens the modal directly in edit mode),
  a delete confirmation, and discovery that shows **only matches while the query
  is non-empty** (full catalog only when empty). Shared modal styles promoted to
  global.

## M20f — Tool inventory + global auto-approve

- **Backend:** `ToolPrefsService` persists a global per-tool auto-approve set
  (`~/.icos/tool-prefs.json`, `TOOL_PREFS_PATH`). `GET /core/tools/inventory`
  lists every tool; `PUT /core/tools/auto-approve/:name` (admin) sets the
  override. The execution path consults it, so an auto-approved tool no longer
  parks for approval. The `execute_code` RPC bridge stays on declared approval.
- **Client:** the Tools tab renders the real inventory and wires the checkbox to
  the server (replacing the static 2-tool `localStorage` stub).

## Unit

Core **1193 unit / 66 e2e**; client **195 tests**; `tsc`/`eslint` + `ng build`

## Live

```
GET  /core/tools/inventory            → 31 tools (25 native + 6 MCP)
PUT  /core/tools/auto-approve/terminal {autoApprove:true}
     → terminal approval:"required" autoApprove:true
PUT  /core/tools/auto-approve/nope    → 404

terminal turn with autoApprove:true   → trace []  (no parking)
terminal turn after resetting to false → trace ["approval_required"]  (parks)
```

The override is honoured by execution and is fully reversible.
