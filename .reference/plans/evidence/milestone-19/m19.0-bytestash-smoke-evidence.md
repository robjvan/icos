# M19.0 — ByteStash smoke test (pre-M19): evidence

> Status: **verified** (2026-10-09). Not a milestone slice — a smoke test of the
> existing MCP client against the live target, done before writing M19 code.

## Target

ByteStash MCP server, `http://192.168.2.10:5000/mcp`, Streamable HTTP, API-key
auth. Registered via `PUT /core/mcp/servers/bytestash`:

```jsonc
{
  "name": "bytestash",
  "transport": "http",
  "url": "http://192.168.2.10:5000/mcp",
  "headers": { "x-api-key": "$BYTESTASH_AUTH" },
  "approval": "required"
}
```

## Results

```
GET /core/mcp/servers
  → { name: bytestash, transport: http, state: connected, toolCount: 6 }

GET /core/mcp/catalog
  → headers: { "x-api-key": "$BYTESTASH_AUTH" }   (reference only, no value)
```

A live conversation turn then exercised the full path:

```
model called mcp_bytestash_list_snippets {}
  → approval_required → approved → resumed
  → tool returned successfully
```

## Conclusions

- The existing client connects over **Streamable HTTP** and authenticates with a
  `$VAR` reference resolved from the container env (`.env` via compose
  `env_file`). No code changes needed for transport/auth.
- All six ByteStash tools are discovered (they appear under the current pooled
  `toolset: 'mcp'`, which M19.1–M19.2 replaces with `mcp-bytestash` + aliases).
- Container → LAN host reachability confirmed.
- Note: `.env` changes require recreating the container (`docker compose up -d`),
  not a bare `restart` — env is read at container start.
