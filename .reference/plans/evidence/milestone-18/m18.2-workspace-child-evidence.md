# M18.2 — Skills as a workspace child: live evidence

> Status: **verified** (2026-10-09). Slice **M18.2**. Per-slice evidence; M18 is
> in progress.

## Decision

Rather than materializing a skill's supporting files into the workspace on use,
the skills catalog is now a **child of the tools workspace**
(`<TOOLS_WORKSPACE_ROOT>/skills`). The workspace is the agent's sandbox, so the
existing file and terminal tools reach a skill's `scripts/`, `references/`, and
`templates/` **directly** — no new tool, no boundary change, no per-use copies.
It also matches the KB plan (`<workspace>/kb`).

## What changed

- `skillsDirPath` defaults to `<workspace>/skills` (was `~/.icos/skills`).
  `SKILLS_DIR_PATH` still overrides. `config.spec.ts` updated.
- `.env.sample` documents the workspace-child default.
- **No tool code changed** — `read_file`, `search_files`, `write_file`, `patch`,
  `terminal`, and `execute_code` already confine to `TOOLS_WORKSPACE_ROOT`, which
  now contains the skills.

### Consequences

- The agent can **read and run** a skill's scripts; it can also `write_file`/
  `patch` a skill (the sandbox model — writes inside the workspace are
  approval-free). `skill_manage` remains for **guarded** edits (frontmatter
  validation + content scan); the seed's no-overwrite rule still protects
  shipped skills on first run.
- The catalog directory (`<workspace>/skills`) is host-visible and editable.
