# M21.1 — Async delegation core: evidence

> Status: **verified** (2026-10-11). Slice **M21.1** (delegation records,
> detached runner, three tools, loop hooks, budgets). M21 continues with
> M21.2 (integration) and M21.3 (hardening + evidence).

## Design

- **Records** (`delegations` table, sessions DB): one row per spawned child —
  parent session/run, child session, goal, budgets, terminal state, bounded
  result summary, cooperative cancel flag. Child turns write normal
  `agent_runs` rows under the child session id; the invocation ledger stays
  the single authority on execution. Restart honestly marks non-terminal rows
  `failed (restart)` — background promises do not survive a restart, and the
  record says so instead of dangling.
- **Runner** (`SubagentRunner`): `spawn` writes the record and launches the
  child turn as a detached background promise via the cron-precedent
  `ModuleRef` lazy resolution (no DI cycle); the parent is never awaited on.
  Concurrency cap (4), per-child budgets (5 iterations / 5 steps / 5 min),
  4000-char truncated summaries. Every exit path lands in the record — a
  rejection can never escape into the parent or crash the process.
  First-terminal-wins settle (a late orphan cannot clobber restart/cancel
  markings). Parked children reconcile onto their run's terminal state on
  the next status read.
- **Tools** (`delegate_task` / `delegate_status` / `delegate_cancel`,
  approval `none` like `cronjob_manage`, toolset `subagents`): refusals
  (disabled, capped, nested, blank goal) are structured results, not throws.
  Flat-only enforced at spawn — a child session calling `delegate_task`
  gets `{spawned:false}`.
- **Loop hooks**: `converse` accepts a per-turn budget override
  (`options.limits`, recorded on the run so resume paths inherit it);
  cooperative cancel checks in `converse` / `resumeTurn` / `resumeStream`
  terminate truthfully (`cancelled`, existing `TurnOutcome.outcome`
  carrier).
- **Real fix found by testing**: `delegate_status` is exempt from the M9j
  repeat-call skip. Polling is repeat-shaped by design (same name+args
  re-reads fresh server-side state); without the exemption a parent could
  only ever poll once — every later poll was swallowed as a duplicate and
  the delegation looked permanently `running`. Spawning stays guarded
  against fan-out; turn budgets still bound polling abuse.
- **Default:** `SUBAGENTS_ENABLED=true` with conservative budgets;
  `false` restores exact pre-M21 behavior. Six vars documented in
  `.env.sample`.

## Live

Real model (deepseek-v4.1-flash via opencode), rebuilt container:

```
POST /core/conversation {"message": "delegate a subagent ... reply immediately
  with just the task_id ... do not wait"}
  → 200 ok, reply: "fc38b0c1-afbb-4c80-a8df-953a164836f2"   (did not block)
GET  /core/sessions → second session bb5b9432 (child, separate transcript)
core log: [SubagentRunner] Delegated "Write a two-sentence brief ..." ->
  fc38b0c1 (child session bb5b9432)

child transcript:
  [user] [Subagent task — ...] Goal: Write a two-sentence brief on why
    SQLite FTS5 is useful for session search / Context: No additional
    context provided.
  [assistant] **Brief ...** (two sentences + an honest verification note:
    it ran session_search itself, got zero matches, and hedged accordingly)

POST /core/conversation {"message": "check delegate_status for task ..."}
  → 200 ok, reply reports State: completed + the child's full summary

isolation: child transcript carries the goal, never the parent's message
nested probe (turn in the child session asking to delegate further):
  → 200 ok, child called delegate_task once, got
  {"spawned": false, "reason": "A delegated child cannot delegate further."},
  reported it accurately — and explicitly declined to route around the
  guardrail via search_platform_tools.

DELETE /core/sessions/<child> → 200, DELETE /core/sessions/<parent> → 200
```

### Notes

- The child used `session_search` on its own initiative (proving children run
  the full loop with their own tool access) and hedged its brief honestly.
- The parent relayed the summary with its own caveat about the child's
  self-reported tool use — appropriate epistemic caution, unprompted.
- No approvals were triggered (research-only subtask); the tagged-approval
  path is exercised in e2e and lands fully in M21.2.
