> M21.2 integration + M21.3 hardening).

## Design (added in this slice)

- **Parked-turn resume from the queue alone**: `approvals.request_id`
  carries the tool-round request that parked (migration included, nullable).
  The web store falls back to it when no parked entry exists — the only
  handle a detached child leaves behind. Without this, a parked detached
  child was unresumable through every surface (web needs its `pendingResumes`
  entry from a foreground turn; Discord needs its card map the same way).
  Found while designing the approval-deadlock walkthrough; fixed rather
  than worked around.
- **Child-turn port** (`CHILD_TURN_RUNNER` + adapter, lazy resolution):
  the first wiring attempt (dispatcher → runner → service) closed a
  construction cycle that hung module boot with no error — only a 5s hook
  timeout. Fixed with the port; the adapter is the single lazy edge.
- **Type-only DI token**: `DelegationRepository` was a type-only import in
  `ConversationService`, so decorator metadata recorded `Object` and Nest
  silently injected `undefined` — the M21.1 cancel checks and the M21.2
  band would have been dead in production with all unit tests green. Audited
  every DI token; that was the only one. Unit specs now construct the
  service with explicit stubs, which is why they never caught it.
- **Status-poll exemption** from the M9j repeat skip (see M21.1 evidence).
- **Fan-out**: concurrency cap + per-child budgets + result truncation;
  no queue — over-cap spawns refuse.

## Live

Real model (deepseek-v4.1-flash via opencode), rebuilt container.

### Fan-out: two concurrent children

Spawning is one tool call per turn (see note below), so fan-out went over
two turns — then both children ran concurrently:

```
turn 1 → 200 ok, reply: "0b335564-..."   (child A spawned, replied at once)
turn 2 → 200 ok, reply: "82b45e1d-..."   (child B spawned, replied at once)
/agents list → 200:
  Delegated tasks (2):
  - 82b45e1d [running] Write a one-sentence definition of SQLite WAL mode
  - 0b335564 [completed] Write a one-sentence definition of an SQLite
    index — An SQLite index is a separate B-tree ...
wait → both [completed] with summaries
```

Both summaries returned in full; sessions cleaned up (parent + 2 children,
all DELETE 200).

### Parked-approval walkthrough (the deadlock case)

```
turn 1 (delegate terminal errand) → 200 ok, task 1cc1923c
child parks on `terminal` approval (approval:required, not auto-approved)
GET /core/approvals?sessionId=<child>&status=pending → 200:
  {id, sessionId, action:"terminal.execute",
   description:"Run a shell command: echo hello-from-child",
   requestId:"99ee8ece-…",
   delegation:{taskId:"1cc1923c-…", goal:"Run `echo hello-from-child`…",
               parentSessionId:"3d2b6e43-…"}}
approve → 200; resume with the approval's requestId → 200 ok:
  stdout `hello-from-child`, exit 0
delegation reconciles to [completed] with the verbatim result as summary
DELETE child → 200, DELETE parent → 200
```

The full loop — park → tagged queue entry → approve → resume-from-queue →
reconciled completion — works with no client holding turn state.

### Notes (honest)

- **Fan-in is sequential, fan-out is parallel.** A first attempt to spawn
  both children in one response was refused (`invalid_call_count`: at most
  one tool call per response), and re-issuing was refused as `repeated_call`.
  The model reported both refusals plainly, invented nothing, and offered
  alternatives. Spawning went over two turns; execution was concurrent after
  that. This is the loop guards working as designed, and it shapes how
  multi-spawn flows must be driven — documented here rather than smoothed
  over.
- **One model glitch observed.** A neutral "Anything new?" turn in the
  fan-out run replied with raw DSML tool-call markup instead of using tools.
  No band conclusion can be drawn from that turn (the band is proven in e2e
  and was confirmed live in M21.2). Deepseek tool-syntax leakage, not a
  server behavior — recorded, not hidden.
- **Approval tagging had its live trigger here**: the parked approval
  carried the delegation line end to end (queue item above), and no approval
  path was bypassed at any point.
